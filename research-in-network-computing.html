Research direction · 02

In-network computing.

Extending the cloud–edge continuum with programmable network infrastructure that can host carefully selected service functions close to users and data flows.

The central question

What should be computed inside the network, where should it be placed, and when does that placement improve an application rather than merely shifting cost and complexity?

01 · Motivation

Beyond packet forwarding

For latency-sensitive applications, sending every task to a remote cloud or even a conventional edge server may be too slow. Programmable switches, SmartNICs, and adjacent accelerators create new execution points along the data path.

02 · Architecture

A wider continuum

My work treats in-network nodes as heterogeneous computing and caching resources within the broader cloud–edge continuum. Orchestration must account for their limited capacities, supported operations, network position, and proximity to active flows.

03 · Use case

Immersive services

I study interactive applications in which service assets, user-specific assets, and rendering tasks have different mobility and reuse patterns. INC can shorten the processing path when placement decisions reflect those distinctions.

04 · Systems view

Practical constraints

  • Programmability and hardware feasibility.
  • Limited memory and compute capacity.
  • Control-plane coordination and placement overhead.
  • Interoperability with cloud and edge resources.

Research outcome

This direction reframes network infrastructure as an active part of service delivery. It provides the architectural basis for in-network rendering farms and for learning policies that decide how distributed resources should be used over time.
